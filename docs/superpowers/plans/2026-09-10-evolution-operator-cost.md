## 一、优化前基线（诚实实测，本机 12 核 WSL2）

工具：`build/bench_individual_representation --cells N --syn-per-cell 8`
（1,048,576 细胞 / 8,388,608 突触；AoS = 1024 列 × 1024 细胞；Flat = 1 列）

| 布局 | 构造 | 深拷贝 | 变异 | 前向 OMP=1 | OMP=4 | OMP=12 | 动态内存 |
|------|------|--------|------|-----------|-------|--------|----------|
| AoS 1024列 | 21.95 ms | **26.57 ms** | **32.62 ms** | 1.99 ms | 0.93 ms | **14.35 ms** | 89.40 MiB |
| Flat 1列 | 8.27 ms | 7.26 ms | 32.19 ms | 1.50 ms | 1.82 ms | 1.84 ms | 89.00 MiB |

**关键反常（优化前既已实测）**：AoS 前向在 OMP=12 下从 1.99ms **崩到 14.35ms**——并行区过订（WSL2 下嵌套/开队开销）。而 Flat 单列无法并行，反稳定 ~1.8ms。

**内存澄清**：AoS 与 Flat 内存几乎相同（89.40 vs 89.00 MiB）→ **内存布局不是瓶颈**。上一轮会话报的「13.5 MiB/个体」为**低估**（仅计 genome 细胞字段，漏 `ExecutionRegisters` 与 io），本专题据此纠正。

## 三、诚实条款（预先声明）

1. **Phase 2 必然改变随机流（语义变更）**：把逐元素 `std::uniform_*`/`std::normal_distribution` 换成计数器式 splitmix64 派生，必然改变「同种子 → 基因」映射。现有位级测试为**自洽比较**（同二进制两次运行），故不受影响；但**这是行为变化，如实披露，不伪装为纯加速，且不得据此宣称任何牌力/策略收益**。
2. **`biases` 不参与变异**：`sdsc_tensor_graph_forward`（`sdsc_runtime.h:66-82`）无 biases 入参 → 变异 biases 不影响前向，属无效开销。本专题**不**引入 biases 变异（那需改前向签名，属独立语义变更，超授权）。
3. **取模偏差**：`mutate_primitive_types` 用 `h % pool_size`（pool=17，非 2 的幂）有极小偏差，如实披露；如需无偏可后续改拒绝采样。
4. **Phase 1 保持 rng 序列**：`cross_into` 的 rng 抽取次数与顺序与旧 `cross` 逐位一致（可证 + H4 测试），故 Phase 1 **不改变演化轨迹**。
5. **Phase 3 数值不变**：并行区只调 `columns_[c].step()`（各列互不写），守卫只决定是否开线程队 → 结果逐位一致；副作用是嵌套调用时失去内层并行（由最外层单点调度补偿）。
6. **合成与任务口径分开报告**：合成算子微基准与真实任务 `evo_sec` 结论可能不同，不得用合成结论冒充任务收益。

### 5e. 最终如实结论与披露

**结论（如实，不粉饰）**：**两块成立、一块不成立**。L1 offspring 缓冲复用（稳态零分配，evolve 端到端 **2.6×**）与 L0 键控并行变异（OMP=12 **4.5×**）成立；**Phase 3 前向守卫无实测收益（H3 不成立）**。**86/86 回归全绿**，L0 改动 task-agnostic。

1. **H2 的收益来自「并行」，不是「计数器 RNG 标量更快」（重要诚实项）**：标量快速路径 OMP=1 仅 1.15×（28.4 vs 32.6ms）——splitmix64 与 mt19937 单元素成本相当。真正的 4.5× 来自**键控 RNG 使逐元素随机量成为 `key^索引` 的纯函数，从而可安全并行且与线程数无关**（实测 OMP=1/4/12 变异 28.4/7.6/7.3ms）。换言之：**上一轮我把根因归为「distribution 开销」，实测只对了一半——主因是变异无法并行**。
2. **H3 不成立——原始基线是测量事故（必读）**：上一节基线表「前向 OMP=12 = 14.35ms」是**首轮冷启动单次采样离群值**。用 `git stash` 复测旧代码（5 次平均）为 **0.48ms**，新代码 0.57ms，**顶层无差异**。原「AoS 前向在 OMP=12 崩到 14ms、Flat 稳定 1.8ms」的对比是**假象**。因此 Phase 3 的 pragma 守卫**不构成性能修复**；其唯一正当性是**防御性**——当 `forward_multi_channel` 被外层并行区（任务层 eval）包裹、且运行环境开启 `OMP_NESTED=true`/`OMP_MAX_ACTIVE_LEVELS>1` 时避免嵌套线程队过订（该嵌套场景本次**未单独实测**，如实标注未验证）。是否保留 Phase 3 由用户裁量；回退不影响 H1/H2。
3. **随机流已改变（语义变更，披露）**：Phase 2 起「同种子 → 基因」映射与旧版不同。任务口径 OOS 从 `0.20 / +9.5%` 变为 `0.85 / +58.4%`——**这是换流的巧合结果，不是被验证的 alpha 改进**（单种子、一次性），**不宣称任何牌力/策略收益**。`*_legacy` 与 `KUN_FAST_MUTATION=0` 可回退旧流。
4. **任务口径近乎无收益（1.03×）**：quant 任务个体仅 43 列（小基因组），缓冲复用与并行变异收益被 eval（前向×步数）主导稀释；合成算子口径的 2.6× 不代表任务收益。**不得用合成结论冒充任务收益。**
5. `biases` 仍不参与变异（前向不消费）；`mutate_primitive_types` 用 `h % 17` 有极小取模偏差（已披露）。
6. 热 copy-assign 的 3.3× 是「分配次数」之差，非字节量（内存 89MiB 两者相同）。
7. **测量方法学教训（本专题自身）**：WSL2 下并行微基准**单次采样极不可靠**（本专题多次出现 443 vs 3600 代/s、14.35 vs 0.48ms 的离群）。凡并行/线程相关结论必须多次采样 + 禁止与他人并发跑基准；本专题 Phase 3 的误判即源于此。
